## Project Overview

This project has been developed to simulate an environmental monitoring and control system utilizing the STM32F103R6 microcontroller and has been built using the arm-none-eabi toolchain, build tools, Eclipse CDT, the Proteus simulator and CubeMX. 

The system has been designed to achieve the following functionalities:
- Monitor ambient temperature using an analog temperature sensor (LM35) and continuously convert the analog signal via the ADC peripheral.
- Measure rainfall intensity through a tipping-bucket rain gauge sensor, processed via a monostable multivibrator to ensure uniform pulse generation.
- Allow user-defined temperature threshold input via a matrix keypad. When the measured temperature exceeds this threshold, an alarm condition is triggered, visually indicated by a bi-color LED.
- Control the fan’s operation based on the current temperature in relation to the configured threshold, utilizing PWM for speed regulation.
- Display real-time sensor data and system status on both an alphanumeric LCD and a virtual serial terminal.

## System Architecture

- STM32F103R6 microcontroller.
- Electromotor (MOTOR) representing the fan, whose speed is controlled by a PWM signal on Timer 3 Channel 1.
- KEYPAD-PHONE (ACTIVE) matrix keypad for user input.
- Temperature sensor LM35 (NATDAC), connected to ADC channel 7 of STM32F103R6, which outputs an analog voltage linearly proportional to the ambient temperature.
- RAINGAUGE (ACTIVE) tipping bucket rain sensor connected via a 74HC221 monostable multivibrator (74HC). The tipping level is set to 0.01 mm. The monostable multivibrator ensures uniform pulse duration of 1 millisecond. 
- Virtual terminal connected through USART1, allowing serial communication for monitoring.
- LCD display LM041L with four lines.
- Bi-color LED (LED-BIRG) with full drive current set to 1 μA, capable of lighting different colors depending on current direction.


## Functional Description

- Temperature Monitoring
The temperature has been continuously read from the LM35 sensor via ADC.
The value has been processed and displayed on the Virtual Terminal in the following format:

```
Temp: <value>
```

The output has been refreshed every 200 ms, conditional on a change in the measured value.

- Rainfall Monitoring
Rainfall intensity has been derived based on the frequency of pulses generated by the RAINGAUGE sensor and 74HC221 monostable multivibrator.
The trigger level has been set to 0.01 mm, resulting in one pulse every 1200 ms at an intensity of 30.0 mm/h.
The rainfall intensity has been shown on the first line of the LCD in the format:

```
Kisa: <value>
```

The value has been refreshed every 200 ms upon change.

- Threshold Temperature Input
The threshold temperature (temp_granica) has been input using the keypad. Initial value of threshold is 30.
The input procedure has been reflected on the fourth line of the LCD in the following format:

```
Thld:(??)=><value>
```

The initial value has been set to 30°C. Upon entry of two digits, the threshold has been updated, and the placeholders reset.

- Bi-color LED Behavior
Green (ON constantly) – when the temperature is below the threshold.
Red (blinking, 1s period) – when the temperature is equal to or exceeds the threshold.
The blinking pattern has consisted of 500 ms ON and 500 ms OFF intervals.

- Fan Speed Control
The fan (motor) has been controlled using PWM.
Behavior based on current temperature:
Below threshold: PWM = 0% (fan OFF).
Threshold to 60°C: PWM = 50% (fan running at half speed).
The PWM duty cycle has been updated every 200 ms based on the latest temperature reading.

## Code Structure

The following modules and functionalities have been implemented as part of this project:

- `...\cubemx\code`:

	- `driver_uart.h`, `driver_uart.c` - A custom driver for the USART peripheral has been implemented, supporting transmission functionalities for asynchronous communication between MCU and Virtuel Terminal.
	
	- `driver_lcd.h`, `driver_lcd.c` - The logic required to control and interface with the LCD display has been fully implemented in this module. A 4-bit data interface has been used to communicate with the LCD, and characters have been rendered in the 5x8 dot matrix format.
	
	- `driver_motor.h`, `driver_motor.c` - Functions have been implemented to control the fan speed. There are three fan speed modes: off, running at 50% of maximum speed, and running at 100% of maximum speed.
	
	- `driver_temper.h`, `driver_temper.c` - The logic for measuring temperature based on the LM35 sensor has been implemented.
	
	- `driver_keypad.h`, `driver_keypad.c` - Logic has been implemented to allow the user to enter a two-digit value via the keypad (keypad scanning), which defines a new temperature threshold. If the current temperature exceeds this threshold, an alarm will be activated (the LED will blink red periodically).
	
	- `work.h`, `work.c` - System initialization. Reading temperature, displaying the current temperature, controlling the fan speed based on the measured temperature, obtaining and displaying rainfall intensity, entering digits via the keypad, and displaying the entered digits on the LCD. Updates occur every 200 ms.

The rest of the code was automatically generated using CubeMX.

## Required Tools

This project requires the following tools:

- **GNU MCU Eclipse IDE (version 2021-06-R)**
- **GNU ARM Toolchain (version 10.2.1)**
- **GNU MCU Build Tools (version 4.2.1-2)**

## Installation Steps

- Extract the archives containing the required tools.
- Add the following directories to the system's PATH environment variable:
    - **build-tools-4.2.1-2\bin**
    - **arm-none-eabi-gcc-10.2.1-1.1\bin**

## Running the Project

- Eclipse CDT:
	- Workspace Setup: 
		- Set the workspace to the **cubemx** folder.
	- Toolchain Setup:
		- Navigate to **Windows -> Preferences -> Workspace -> Arm Toolchains Paths**.
        - Set the Default Toolchain to: **xPack FNU Arm Embedded GCC**
        - Set the Toolchain Folder to: **...\arm-none-eabi-gcc-10.2.1-1.1\bin**
        - Set the Build Tools Folder to: **...\build-tools-4.2.1-2\bin**
	- Importing the Project:
		- Select **Import -> C/C++ -> Existing Code as Makefile Project**.
        - Set the Existing Code Location to **...\project\cubemx\code**.
        - Select the Toolchain: **Arm Cross GCC**.
	- Project Settings:
		- Navigate to **Properties -> C/C++ Build -> Settings** and click **Apply and Close** (wait for the indexer to process paths).
		- Navigate to **Properties -> C/C++ General -> Paths and Symbols -> Symbols**  and add the following symbols as GNU C:
			- **USE_HAL_DRIVER**
			- **STM32F103x6**
	- Creating Build Targets:
		- Right-click on the project and select **Build Targets -> Create**.
		- Create the following targets: 
			- **all**
			- **clean**
	- Building the Project:
		- Double-click the **all** target to build the project.
		
- Proteus:
	Run as Administrator: Open Proteus with administrator rights.
    Open proteus project file. 
	For the STM32F103R6 program file, choose one of the following options:
		- **...\build\code.elf**
		- **...\build\code.hex**
